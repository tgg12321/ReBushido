# tools/

What each thing here is for. Unless it says otherwise a script runs from the
repository root; the ones that read the build's output run inside WSL after a
build.

## Building

| | |
|---|---|
| `setup_wsl.sh` | One-time set-up on Ubuntu: packages, the Python virtualenv, the compiler |
| `build_cc1.sh` | Builds the compiler, GCC 2.7.2's `cc1`, into `gcc-2.7.2/` ([`docs/COMPILER.md`](../docs/COMPILER.md)) |
| `cc1-reorg-negate-rtx-decl.patch` | The one change made to the compiler's source: a missing declaration that crashes it on a 64-bit host |
| `build.sh` | `bash tools/build.sh [check\|clean-check\|movovl\|shift\|modern\|rebushido\|rebushido-disc\|quickboot\|quickboot-disc]`: activates the virtualenv and runs `make`, hiding the assembler's noise and exiting with `make`'s status; `bash tools/build.sh test` runs the tests, `bash tools/build.sh playtest [name...]` builds the play tests' discs and runs them |
| `checks.sh` | `make checks` (`bash tools/build.sh checks`): every check GitHub Actions runs, in its order (the counts, the lint, `modern`, `test`, the game's bytes, the overlay's, `shift`, then ReBushido's build, tests and `modern`), each one's output in `build/checks/<name>.log`, and a summary; exit 1 if any failed. The list is the workflow's: change both together |
| `rebushido.py` | The ReBushido build's link ([`docs/REBUSHIDO.md`](../docs/REBUSHIDO.md), "How it links"): `ld` writes `build/rebushido/rebushido.ld` from `bb2.ld` and the objects, adding what `bb2.ld` does not place; `fit` reports the program's size and the room left, and fails if it does not fit. `make rebushido` runs both |
| `quickboot.py` | The fight a quick-boot build starts ([`docs/REBUSHIDO.md`](../docs/REBUSHIDO.md), "Booting straight into a fight"): `--list` prints what each `QB_` variable of the `Makefile` can be, by the game's own names; `check` is what `make quickboot` runs before it compiles, `write` what `make quickboot-disc` leaves beside the disc image |
| `maspsx/` | The stand-in for Sony's assembler ASPSX 2.34: a modified copy of [mkst/maspsx](https://github.com/mkst/maspsx) |
| `make_psexe.py`, `elf32.py` | Put the PS-X EXE header in front of the linked image; the small ELF reader it uses (which also reads the sections and names of the 64-bit port's program) |
| `gcc-2.7.2/` | The compiler's source and binary (not in git; made by `build_cc1.sh`) |

## Checking the source

| | |
|---|---|
| `count.py` | Counts what `docs/STATUS.md` reports: functions in C and in assembly, listings, `FAKE` notes by kind, `goto`s by verdict, casts, the linker scripts' lines and gaps, files, `unkNN` and `D_` names. It checks every `FAKE` note and `goto` of the source against the tables of `docs/FAKES.md`; `--check` fails if they disagree (a gate), `--notes` lists each note with its kind. Needs no build. It counts the source as the matching build compiles it (what is inside an `#if` of ReBushido's switches left out) and lists ReBushido's files, switches and `#if` blocks apart |
| `casts.py` | Counts the casts of the game's files and the overlay's own, by kind; `count.py` runs it |
| `lint.py` | Counts the checklist of `docs/STYLE.md` in the game's own files, per file and in total: contentless names, bare numbers, `extern` and prototypes in `.c` files, declarations in the wrong header, `unkNN`, missing comments and the rest (its docstring lists them). `--file` lists a file's findings, `--list <check>` one check's; `--check` fails if a count is over `lint_baseline.tsv` (a gate), `--update` rewrites that. Needs no build. It reads `src/rebushido/` too and both sides of every `#if` of ReBushido's switches, and `rb-flag` counts the switches asked wrongly |
| `shift_test.py` | `make shift`: relinks with padding, fails if anything depends on where code or data is, and reports the room left below the fixed buffers |
| `modern/check.py` | `make modern`: gives the game's C (`src/main/*.c`, `movovl/src/*.c`) to the host's modern `gcc` as 32-bit code, with `-Wall -Wextra`, more warnings and `-fanalyzer`, only for what it says: nothing it makes is used. `modern/shim.h` and the headers it rewrites into `build/modern/include/` stand in for what only the old compiler or the PlayStation has (assembly functions, GTE macros, a cast that is assigned to). Writes `build/modern/report.txt`; `--check` fails on a finding of a serious kind (something read before it is set, an index past an array, a wrong format, a missing return) that `modern/baseline.tsv` does not have, `--update` rewrites that, `--raw <file>` shows the compiler's own text. `modern/verdicts.tsv` holds what was decided about each finding read: the tool is wrong, the original's bug, or how the bytes need it. Needs WSL's `gcc`, no build |
| `../tests/run.py` | `make test` (`bash tools/build.sh test [-v] [name...]`): builds the game's pure functions for the host, from the game's own `.c` files, and compares what they compute with real maths, hand-made cases and the disc's data; a line a test, exit 1 if one fails. With `--rebushido` every test is run a second time as a 64-bit program. The tests, how to add one and what they stand on: [`tests/README.md`](../tests/README.md). Needs WSL's `gcc` and `python3`, no build; the disc's tests are skipped without the disc |

## Playing the game by script

On the developer's machine only: these need your own retail image and
PCSX-Redux. How to run them and how a test is written:
[`tests/play/README.md`](../tests/play/README.md).

| | |
|---|---|
| `playtest.py` | `make playtest` (`bash tools/build.sh playtest [name...]`; `python tools/playtest.py [name...]` with the discs already built): runs the tests of `tests/play/` in the emulator with no window, one run at a time, each ended by a time limit; a table of test, result and time, exit 1 if one failed; "skipped", and exit 0, where the emulator or a disc is missing. Pictures and logs go to `build/playtest/`. A test's disc `port` is the native port's program, run in the emulator's place with the same plan (through `wsl` from Windows). `--symbols ELF OUT` writes the table of a built disc's names, which the disc targets run |
| `play/runner.lua` | The emulator's side: the one script it is given. It reads the run's plan (data, not generated Lua), presses the pads, writes down the watched values at each checkpoint, takes the pictures, and ends the run on a crash (an exception, the program counter astray, no frame for too long) |
| `play/launch.py` | Starts the emulator so that nothing of it is seen or left: on Windows on a desktop of its own, with the system's error boxes off, in a job that is ended as a whole; reports any visible window and any process left |
| `play/snapshot.py`, `play/picture.py` | What two runs of a play test wrote at their checkpoints, compared, for `playtest.py` and `port_compare.py`: the game's memory by the names of the source, and all of video memory pixel for pixel, with how many pixels differ, where, and by how much ([`tests/play/README.md`](../tests/play/README.md), "Memory at a checkpoint", "The picture") |
| `play/spu.py` | The sound chip of two runs of a play test, compared, for `playtest.py`: sound memory byte for byte from `0x1000` on and the registers a program writes. It cuts the emulator's chip out of the whole saved state the emulator's script writes, which is the one way a script has to it ([`tests/play/README.md`](../tests/play/README.md), "The sound") |
| `gte_probe.py` | After the play test `gte_model` has failed: the cases the emulator and the native port's C made different things of, register by register, and for a case of the renderer's word by word of memory (it reads what the probe left, and runs the host tests' programs for the port's side). `tests/play/README.md`, "The GTE probe" |

## Working on the source

| | |
|---|---|

| `normalize_lf.py` | Makes a file's line endings LF |
| `rename.py` | Whole-word rename, from a map file (`old new` a line), across everything the build reads; renames a function's listing in `asm/funcs/` too |
| `objdiff.py` | Per-function comparison of any two object files: which functions changed, and how ([`docs/MATCHING.md`](../docs/MATCHING.md), "The loop") |
| `listings.py` | Checks the names in `asm/funcs/` against the build; `--write <function>...` writes the disassembly of any function of the build into `build/reference/` |
| `symbol_addrs.py` | Writes `config/symbol_addrs.txt`, every symbol and its address with the functions marked, from the built ELF; `--check` says whether it is current |

## The disc and its files

Formats and usage: [`docs/formats/`](../docs/formats/README.md). These need
your own copy of the disc.

| | |
|---|---|
| `extract_iso.py` | Extracts the files of a disc image to `disc/` |
| `rebushido_patch.py`, `rebushido_release.py` | A ReBushido release: the BPS patch against the retail image, made and applied with the standard library alone, and what `make rebushido-patch` puts beside it (`docs/REBUSHIDO.md`, "Making a release") |
| `patcher/patcher.c` | The players' patcher, `ReBushidoPatcher`: one file of C that applies a release's patch to the player's image, with the "open file" window and message boxes on Windows and plain arguments and exit codes in a shell. `make patcher` builds it for the host and for Windows (mingw-w64) into `build/release/` (`docs/REBUSHIDO.md`, "Applying the patch") |
| `build_disc.py` | Builds a disc image from the original plus a rebuilt executable and replaced files |
| `unpack_all.py` | An inventory of every asset file under `disc/` |
| `inspect_ndata.py`, `repack_ndata.py` | The NDATA archive (models, stages, weapons, cutscenes) |
| `inspect_bbm.py`, `inspect_windat.py` | Motion files and the win-pose table |
| `inspect_stage.py`, `repack_stage.py` | `STAGE*.BIN` and the other container files |
| `inspect_bnk.py`, `repack_bnk.py`, `repack_vab.py` | The `.BNK` texture blocks and the `.SE` sound banks |
| `inspect_tim.py`, `repack_tim.py` | TIM pictures, to and from PNG |
| `inspect_str.py`, `inspect_movovl.py` | The opening movie's stream and the movie overlay's executable |

Each `repack_*` has a `--roundtrip` mode that unpacks and repacks the disc's
own files and checks the result is identical.

## The native port

[`docs/PORT.md`](../docs/PORT.md).

| | |
|---|---|
| `port_build.py` | `make port` (`bash tools/build.sh port`) runs it twice: it builds the native port from the game's C with the port's switch on, Sony's library code where it is plain arithmetic (libgte, libsnd, libspu and single files of others), and `src/port/`, with 64-bit pointers or with 32-bit ones (`--bits N`, or `PORT_BITS`; [`docs/PORT.md`](../docs/PORT.md), "64 bits"). The default's program is `build/port/rebushido`, the other's `build/port64/rebushido` or `build/port32/rebushido`. An x86 Linux program with no C library, as the host tests are: it needs the host's `gcc` and nothing else, and says so where that `gcc` cannot make one (`--host` asks only that). The game's files are compiled as `tests/run.py` compiles them, with three warnings as errors that hold the source to `ADDR()` and `PTR()`; the port's own with `make rebushido-modern`'s warnings as errors. The game's variables are linked in the PlayStation's order, by a script it writes; it prints how many neighbours are as far apart as there and writes the others to `layout.txt` beside the program. Beside the program it writes `rebushido.sym`, the program's names, the values of `tests/play/state.toml` and, for a 64-bit program, how each variable that grew lies against the PlayStation's; the program reads it for `--trace`, for a plan and to say where it crashed, and `playtest.py` to compare. `--list` names the files |
| `port_layout.py` | Run by `make port` after both programs are built, with `--check`: the size of every structure and the place of every member in the 32-bit port, the 64-bit port (their debug information, by `readelf`) and the PlayStation program (a probe of `sizeof` and offsets through the game's own `cpp` and `cc1`). A structure that is not laid out the same in all three has to be in `config/port_layout.txt` with why it may differ: one that is not fails it, and so does a line for a structure that no longer differs. `--table` prints every structure in the three. `port_build.py` asks it how a variable of the 64-bit program lies against the PlayStation's (`console_runs`) |
| `port_casts.py` | Run by `make port`, with `--check`: finds every pointer the 64-bit port makes from a number that is not a 32-bit address, which the compiler itself does not report: a cast whose operand is already 64 bits wide (`memory + 2 * sizeof(PrimPool)`, where `sizeof` widens the `s32` with its sign), and a negative number written into the source (`(SpriteSheet *)-1`). It reads the SSA form the compiler makes of each file of the game (`-fdump-tree-ssa`), where every value has its type. Each place wants `ADDR()` |
| `port_sdl_build.py` | `make port-sdl` and `make port-sdl-windows` (`bash tools/build.sh port-sdl`): builds the native port with a window, `build/port-sdl/linux/rebushido` for this host and, with `--windows`, `build/port-sdl/windows/rebushido.exe` with MinGW (`SDL2.dll` put beside it, and `rebushido-headless.exe`, the program without a window for Windows), with 64-bit pointers or with 32-bit ones (`--bits N`, or `PORT_BITS`, which puts the other size in `linux32/` or `windows32/`). The same files as `port_build.py` compiles, compiled the same way, then the window's (`src/port/window/`), the remastered renderer's backend (`src/port/gl/gl_draw.c`, which asks OpenGL for nothing at build time: the window looks its functions up), SDL 2 and a C library. The program is linked 2 MB up and its variables have six megabytes, where the build without a window has four: it carries the window, SDL and the renderer's two tables as well. The game and the port are linked into one object first and every name in it but the port's made that object's own, so that the C library and SDL never meet the game's `main`, `printf` or `open`; what the object still asks for must be the host's functions. Each variable is given the boundary the PlayStation's compiler gives it, so that small neighbours stay neighbours: in an ELF object as `port_build.py` does it, and in a Windows one by the assembly it writes between the two steps of the compile and by the object's own section flags (`cap_alignment_coff`). It writes the program's names beside it, with how a variable that grew lies against the PlayStation's, and counts the neighbours as `port_build.py` does. Local: no check runs it. `--host` says whether the machine can build it and what is missing ([`BUILD.md`](../BUILD.md), "The port with a window") |
| `port_gl_build.py` | Builds the prover of the port's remastered renderer, `build/port-gl/rebushido-gl`: the same files as `port_sdl_build.py` compiles, linked the same way, with `src/port/gl/` and EGL in place of SDL. The program takes an OpenGL 3.3 core context from EGL's surfaceless platform, so it needs no window, no display and no graphics card (Mesa's software driver draws it). Local: no check runs it. `--host` says whether the machine can build it ([`BUILD.md`](../BUILD.md), "The remastered renderer, with nothing shown") |
| `port_remaster_prove.py` | Measures what "Graphics: Remastered" adds, stage by stage ([`docs/PORT.md`](../docs/PORT.md), "Remastered"): for each stage and each setting of the draw distance, the smoothing and the shape of the picture it runs the prover into a versus fight on that stage, runs the first fighter across it, and reports the primitives a frame drew, the room left in every store of a fixed size the drawing path fills, and the time; with `--shots`, the hardware's picture and the software GPU's at the same blanks, as PNGs. The stage is asked for by a `poke` line of the plan, which **changes what the game computes**, so these runs are not the proof that play is untouched: `port_gl_prove.py` is. Local: it needs the program above and your own disc image |
| `port_png.py` | `python tools/port_png.py crop IN OUT X Y W H [ZOOM]`, `beside OUT IN...`, `diff A B [X Y W H]`: cuts a rectangle of one of the port's PNGs and enlarges it blocks and all, puts pictures side by side, or says how many pixels of two differ and by how much. The standard library alone; it reads the three-channel, unfiltered PNGs the port writes |
| `port_gl_prove.py` | Proves the remastered renderer with nothing shown ([`docs/PORT.md`](../docs/PORT.md), "Remastered"): for each of the three port play tests it writes the plan for that program, runs it at scale 1 with everything that changes a value turned off and compares every picture with the software GPU's pixel for pixel, runs it again at the scale asked for and writes both pictures as PNGs, and runs the game with the remastered renderer on and off to hold the two traces to each other. It prints what it measured and leaves everything in `build/remaster/`. Local: it needs the program above and your own disc image |
| `port_fps_prove.py` | Proves the pictures the port draws between the game's frames, with nothing shown ([`docs/PORT.md`](../docs/PORT.md), "More pictures a second"): for each of the three port play tests it draws every game frame as N pictures, the first the frame on show and the last the frame after it, and holds three things — the first picture is the game's own pixel for pixel, every picture in between is farther from the first and nearer the last than the one before it, and the point the renderer watched lies between its two ends. It also runs the game with the pictures on and off to hold the two traces to each other, and writes a strip of consecutive pictures of a fight as PNGs. Everything goes into `build/fps/`. Local: it needs `build/port-gl/rebushido-gl` and your own disc image; run it once for each pointer size, since `port_gl_build.py` writes both sizes to the one name |
| `port_order.py` | Run by `make port` after the build, with `--check`, once for each size (`--bits N`): finds every place in the port where the order in which an expression's operands and arguments are evaluated is the compiler's choice **and** matters, because one of them is a call that may write what another reads. The PlayStation's compiler makes an expression's calls in the order written and reads variables after them; a PC's works the arguments out from the last and reads as it goes ([`docs/PORT.md`](../docs/PORT.md), "What the PlayStation's compiler decided"). It compiles each file as `port_build.py` does, reads the statements the compiler made (`-fdump-tree-gimple-lineno`) and what every function may write, and holds what it finds to `config/port_order.txt`, the places that were looked at with why each makes no difference; a place not there fails it. `--update` writes that list again and keeps the reasons; `--all` also shows the places where the order differs and cannot matter |
| `port_compare.py` | `python tools/port_compare.py TEST [CHECKPOINT...]`: where two runs of a play test differ, from what `playtest.py` left in `build/playtest/TEST/`: at each checkpoint the values that differ and each run of bytes of the `[snapshot]` memory that does, by variable and offset, with the bytes on each side. An address of the same place of the same name in both programs is not a difference. `--vram` compares video memory too, where a checkpoint wrote it (`tools/play/picture.py`): how many pixels differ, where and by how much, and pictures of each that does. `--new` shows only what did not differ at the checkpoint before, `--first` stops at the first that differs, `--only NAME` takes one piece. For finding where the native port leaves the emulator ([`tests/play/README.md`](../tests/play/README.md), "Finding where two runs part"). `play/snapshot.py` is the comparison itself, which `playtest.py` uses too |
| `port_wav.py` | `python tools/port_wav.py FOLDER`: listens to a run of the native port by numbers. FOLDER has the run's `sound.wav` (`--wav`) and its output as `run.log`. For each section of the run, between the plan's checkpoints: its length, each side's peak and RMS, the samples at full scale, the longest silence, the voices the chip started and the sounds the game asked for; then the runs of clipping, the largest step between two samples and the run's last quarter second. Writes `envelope.png` (peak and RMS every 20 ms, the checkpoints and key-ons marked) and `spectrogram.png` (0 to 11 kHz), with the standard library alone ([`docs/PORT.md`](../docs/PORT.md), "Sound") |
| `card.py` | `python tools/card.py list FILE`: a PlayStation memory card image, 128 KB, listed, checked, with a file taken out of it or put into it (`check`, `extract`, `insert`, `delete`, `format`). It reads the images the native port writes (`--card1`, `--card2`) and the ones an emulator writes, which are the same thing; the format is written out from the rules in it, as in `src/port/card.c` ([`docs/PORT.md`](../docs/PORT.md), "The memory card"). The standard library alone, and it reads no game data |
| `port_gte_macros.py` | Writes Sony's GTE macros (`include/psxsdk/inline_c.h`, `inline_o.h`) again as C on the port's GTE (`src/port/gte.c`), an instruction a statement, into `build/port/include/`. The builds with the port's switch on put that folder first: `tests/run.py --rebushido` and `tools/modern/check.py --rebushido` call it. `--list` names the macros left out (those with no instruction word in Sony's header). An instruction it has no C for stops it |
