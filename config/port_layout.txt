# The structures that are not laid out in the 64-bit port as on the PlayStation,
# and why each may be (tools/port_layout.py; docs/PORT.md, "64 bits"). Each
# keeps ordinary pointers, which are 8 bytes there, and so grows. A structure
# may be here only if it is never laid over memory that something else lays
# out (a file, the scratchpad, the console's RAM, another structure), is
# never given room by a number written into the source, and is reached only
# through its members' names. Every other structure with a pointer keeps it
# in a PTR32 slot (include/common.h) and is the same in all three builds.
#
#   NAME  why it may grow

# The fighters: two of them, the program's own array (g_fighters). No file
# is laid over one, nothing takes its size or a member's address for an
# array, and the play tests hold both, member by member, to the emulator's
# (tools/playtest.py reads the 64-bit port's as the PlayStation lays them
# out).
Fighter  g_fighters, the program's own array; held to the emulator's member by member

# A 2D screen's frame: the cursors of its primitives and the context its
# draw functions are handed, which are locals of the function that draws
# the frame. A MenuDrawCtx is handed to menu_DrawTitleRule as a MenuCtx, one
# word out (the original's behaviour, select.c): in both the words are a
# number or a pointer each, in the same order, so one word out is one
# member out in the 64-bit port as well, and the rule is drawn where the
# PlayStation draws it (the play test port_picture holds the screen to the
# emulator's, pixel for pixel).
PrimCursors   a local of the frame's draw function; its members are reached by name
MenuCtx       a local of the frame's draw function
MenuDrawCtx   a local of the frame's draw function
MenuTopFrame  a local: the top menu's locals in one structure
SpriteDraw    a local: a request to draw a sheet

# The program's own tables and arrays, filled by the compiler or by name.
ArenaBlock          g_arena_blocks, the program's own array
BitStream           inside BitTrack
BitTrack            g_bitstream_tracks, the program's own array
Cloth               g_cloths, the program's own array
ClothDesc           a local of cloth_model.c
MotionDecoder       g_motion_decoders, the program's own array
MotionDecoderCache  inside MotionDecoder
MotionSections      g_motion_common_sections and g_motion_fighter_sections, the program's own
MotionSetFile       g_motion_set_files, a table the compiler fills with the names' addresses
NavChain            the stages' tables of obstacles (cpu_data.c), filled by the compiler
NavSet              g_cpu_stage_obstacles, the same
RbOption            ReBushido's table of options, filled by the compiler
SoundRequest        g_snd_queue, the program's own array
StageHooks          g_stage_hooks, a table of functions the compiler fills

# The remastered renderer's side channel (src/port/remaster.c): tables of
# the port's own, never laid over anything, whose key is an address and so
# is wider in the 64-bit program.
AnchorSlot the port's own: a HUD primitive's edge, keyed by an address
EffectSlot the port's own: an effect's quad of the side channel, keyed by an address
FaceSlot   the port's own: a face of the side channel, keyed by an address
PointSlot  the port's own: a point of the side channel, keyed by an address
ShadowCaster the port's own: a shadow node's caster, keyed by an address

# The renderer's C (render_asm.c under RB_PORT): what the listings keep in
# registers.
RenderWalk  the port's own: the walk's registers as a structure
TileSplit   the port's own: a local of the tiles' cutting

# Sony's: the sequencer's state and its table of functions (libsnd), which
# the game never gives memory of its own (it plays no sequence), and the
# BIOS's directory entry, which the port's card stubs never fill.
SeqStruct  Sony's libsnd, in the library's own memory
_SsFCALL   Sony's libsnd: a table of functions
DIRENTRY   the BIOS's directory entry: the port has no card yet

# The mods' PNG reader and writer (src/port/png.c): locals that hold a
# pointer to the file's bytes and to where the pixels go.
PngInflate  the port's own: a local of the inflate
PngWriter   the port's own: a local of the writer

# The fixed memory's table (src/port/memory.c): each piece's text, a
# pointer; a constant table nothing of the game's is laid over.
FixedMemory the port's own: a piece of memory at a fixed address and its name

# stb_vorbis (src/port/vorbis.c, src/port/vendor/stb_vorbis.c): the Ogg
# decoder of a mod's music, as it ships. Its structures live in the memory
# music.c gives it and are reached by their members' names; nothing of the
# game's is laid over them, and none is the game's state.
Codebook            stb_vorbis's own, in the decoder's memory
Mapping             stb_vorbis's own, in the decoder's memory
Residue             stb_vorbis's own, in the decoder's memory
stb_vorbis          stb_vorbis's own, in the decoder's memory
vorb                stb_vorbis's own: stb_vorbis by its other name
stb_vorbis_alloc    stb_vorbis's own: a local, the memory it is given
stb_vorbis_comment  stb_vorbis's own: a local, the file's tags

# Monocypher's (src/port/vendor/monocypher/, as shipped; include/
# port_monocypher.h): its contexts are locals of its own functions and of
# the port's callers, which reach them by name alone; nothing is laid over
# one, and none is the game's state.
crypto_argon2_extras    Monocypher's, a caller's local: never laid over memory
crypto_argon2_inputs    Monocypher's, a caller's local: never laid over memory
crypto_blake2b_ctx      Monocypher's, a local of its own functions
crypto_poly1305_ctx     Monocypher's, a local of its own functions
crypto_sha512_ctx       Monocypher's, a local of its own functions
crypto_sha512_hmac_ctx  Monocypher's, a local of its own functions
